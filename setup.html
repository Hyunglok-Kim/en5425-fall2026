1 · Environment1 · 개발 환경

Python 3.11 in an isolated environment named en5425, created with conda or uv — your choice, but you must be able to export and rebuild it (HW0 checks this from a fresh clone).conda 또는 uv로 만든 en5425라는 이름의 격리된 환경에 Python 3.11을 준비해요 — 어느 쪽이든 좋지만, 환경을 export하고 다시 빌드할 수 있어야 해요 (HW0가 fresh clone에서 이를 확인해요).

# Option A — conda (Miniconda is enough)
conda create -n en5425 python=3.11
conda activate en5425
pip install torch numpy pandas xarray matplotlib
conda env export --from-history > environment.yml   # commit this

# Option B — uv
uv init en5425 --python 3.11 && cd en5425
uv add torch numpy pandas xarray matplotlib
# pyproject.toml + uv.lock are your export — commit both

Configure git with your real name and university email — commit history is graded evidence in this course.git에 실명과 학교 이메일을 설정해 주세요 — 이 강의에서 commit 히스토리는 채점되는 증거예요.

git config --global user.name  "Your Real Name"
git config --global user.email "you@gm.gist.ac.kr"
  • Editor: VS Code or the editor of your choice — anything you are fast in.Editor: VS Code 또는 손에 익은 편집기 — 빠르게 쓸 수 있는 것이면 무엇이든 좋아요.
  • AI coding agent (required, at least one): Claude Code, Codex, or Cursor. Agents are mandatory tooling here — and you remain accountable for every line they write (see the AI coding agent policy).AI 코딩 에이전트 (필수, 최소 1개): Claude Code, Codex, 또는 Cursor. 에이전트는 이 강의의 필수 도구예요 — 그리고 에이전트가 쓴 모든 줄에 대한 책임은 여러분에게 있어요 (AI 코딩 에이전트 정책 참고).

3 · Your semester repository3 · 학기 repository

All of your graded written work — entrance tickets, research notes, labs, the capstone — lives in one private GitHub repository that you own.채점되는 모든 서면 작업 — entrance ticket, research note, lab, capstone — 은 여러분이 소유한 하나의 private GitHub repository에 모여요.

  1. Open the template repo en5425-student-template in the course GitHub organization and click Use this template → Create a new repository. Name it en5425-<your-github-username> and set it to Private.강의 GitHub organization의 템플릿 repo en5425-student-template을 열고 Use this template → Create a new repository를 클릭해요. 이름은 en5425-<your-github-username>으로 하고 Private으로 설정해요.
  2. Invite the instructor as a collaborator (Settings → Collaborators; the instructor's GitHub handle is announced in class and on LMS).담당교수를 collaborator로 초대해요 (Settings → Collaborators; 교수님의 GitHub handle은 수업과 LMS에서 공지돼요).
  3. Clone it over SSH and work in it all semester.SSH로 clone해서 한 학기 내내 그 안에서 작업해요.
your-repo/
├── labs/        # one folder per weekly lab (code, figures)
├── memos/       # weekNN.md — entrance tickets
├── notes/       # research notes, one per lab
├── project/     # capstone: proposal, milestones, final report
└── hw0/         # the gate assignment

Conventions — these are graded habits, not suggestions:규칙 — 제안이 아니라 채점되는 습관이에요:

  • Entrance ticket (memos/weekNN.md) pushed 24 h before class; the push timestamp is the submission time.Entrance ticket(memos/weekNN.md)은 수업 24시간 전까지 push해요. push 시각이 곧 제출 시각이에요.
  • A research note in notes/ after every lab, using the course template (What I did / What I learned / What confused me / Open questions).매 lab이 끝나면 notes/에 research note를 남겨요. 강의 템플릿 (What I did / What I learned / What confused me / Open questions)을 사용해요.
  • Commit at every lab checkpoint with informative messages — commit history is part of AI-agent accountability, and one giant "final" commit reads as exactly what it is.모든 lab checkpoint에서 의미 있는 메시지와 함께 commit해요 — commit 히스토리는 AI 에이전트 책임의 일부이고, 하나의 거대한 "final" commit은 딱 그렇게 보여요.
  • Never commit data or model checkpoints. The template ships a .gitignore that covers data/, *.ckpt, *.pt, and friends — keep it intact.데이터와 model checkpoint는 절대 commit하지 않아요. 템플릿에 data/, *.ckpt, *.pt 등을 덮는 .gitignore가 들어 있어요 — 그대로 유지해 주세요.

4 · Course materials4 · 강의 자료

Lecture notebooks, lab scaffolds, and the smoke test live in the course repo. Clone it once and pull weekly:강의 노트북, lab scaffold, smoke test는 강의 repo에 있어요. 한 번 clone하고 매주 pull해요:

git clone git@github.com:gist-en5425/course.git
cd course && git pull        # run before every session
Never edit inside the clone. Copy notebooks and scaffolds out into your own repo (e.g., into labs/weekNN/) before touching them — local edits will collide with the weekly git pull, and your work belongs in your repository, where it is graded.clone 안에서는 절대 수정하지 마세요. 노트북과 scaffold는 손대기 전에 자신의 repo (예: labs/weekNN/)로 복사해요 — 로컬 수정은 매주의 git pull과 충돌하고, 여러분의 작업은 채점이 이루어지는 여러분의 repository에 있어야 해요.
