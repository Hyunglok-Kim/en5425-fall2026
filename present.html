11/91 · Purpose and evaluation contract1 · 목적과 평가 계약
  1. Question and hypothesis — one sentence each; why pretraining might help this task.
  2. Task, place, period, labels — one line each; the label source and its weakness.
  3. Success, defined now — the metric (formula, aggregation and weighting), a practical win threshold, and the four rows by name: random-init control, supervised baseline that tries to win, frozen probe, fine-tuned model.
  4. Evaluation contract — blocked train / validation / test; tuning and checkpoint selection on validation only; ≥ 3 seeds per stochastic row; error bars by paired block bootstrap (template below the baselines on the Capstone page). The test split stays sealed until the recipes are frozen on 4 Dec.
  5. Base model and budget — candidate model, exact revision, licence, size; free-tier GPU-hours for the four rows, tuning, one ablation and restarts; what you shrink if it does not fit (the plan, never the evaluation).
  6. Risk and plan B — the one thing most likely to break; amendments to the contract are dated and made before the runs they affect. Repo: PREREG.md v1; split manifests committed in the 9 Nov studio before any capstone training or probe fitting.
  1. 질문과 가설 — 각각 한 문장; 이 task에 pretraining이 왜 도움이 될 수 있는지.
  2. task · 지역 · 기간 · 라벨 — 각 한 줄; 라벨 출처와 그 약점.
  3. 성공 기준을 지금 정하기 — 지표(공식, 집계·가중 방식), 실질적인 ‘이김’의 문턱, 그리고 네 행의 이름: random-init control, 이기려고 하는 supervised baseline, frozen probe, fine-tuned model.
  4. 평가 계약 — 블록 단위 train / validation / test; 튜닝과 checkpoint 선택은 validation에서만; 확률적 행마다 seed 3개 이상; error bar는 paired block bootstrap(템플릿은 Capstone 페이지의 baseline 아래). test split은 레시피를 고정하는 12/4까지 봉인.
  5. base model과 예산 — 후보 모델, 정확한 revision, 라이선스, 크기; 네 행·튜닝·ablation 1개·재시작을 위한 무료 티어 GPU-hours; 안 맞으면 무엇을 줄일지(계획을 줄이지, 평가를 줄이지 않기).
  6. 리스크와 plan B — 가장 깨지기 쉬운 것 하나; 계약 수정은 날짜를 적어 해당 실험 전에. repo: PREREG.md v1; split manifest는 11/9 스튜디오에서 어떤 학습·probe보다 먼저 commit.
11/162 · Data archaeology and model design2 · 데이터 조사와 모델 설계
  1. Project data — source, licence, the download command, extent and shape, label provenance and known errors; a gallery of actual model inputs.
  2. Base-model archaeology — its pretraining corpus: sensors or variables, geography and dates, filters, observation vs derived-map targets, licence, and known or unknown overlap with your evaluation data; cite the paper or config revision; mark the unknown UNVERIFIED.
  3. Frozen manifests — train / validation / test counts, label distribution, block map, leakage checks; show the commit made before any training.
  4. Input contract — bands or variables, units, gaps and clouds; keep the pretrained model’s expected normalisation; fit any new statistics on project training data only.
  5. Model design — input → tokens → encoder → target shapes; architecture, pretraining objective and masking if used; connect one choice to your Week 7 mini-MAE evidence.
  6. Pilot plan, before running it — two mini-MAE sizes on the Week 7 corpus at a fixed time budget, their probes, and a short adaptation pilot of the public model; compute caps and pass/fail criteria. Repo: data/, split manifests, data card, BASE_MODEL_AUDIT.md.
  1. 프로젝트 데이터 — 출처, 라이선스, 다운로드 명령, 범위와 모양, 라벨 출처와 알려진 오류; 모델 입력 그대로의 갤러리.
  2. base model 고고학 — 그 pretraining 코퍼스: 센서·변수, 지역과 기간, 필터, 관측 vs 파생 지도 target, 라이선스, 내 평가 데이터와의 겹침(알려진 것·모르는 것); 논문·config revision 인용; 모르는 것은 UNVERIFIED로 표시.
  3. 고정 manifest — train / validation / test 개수, 라벨 분포, 블록 지도, 누수 점검; 학습 전에 만든 commit을 보여 주기.
  4. 입력 계약 — 밴드·변수, 단위, 결측과 구름; pretrained 모델이 기대하는 정규화는 그대로, 새 통계는 프로젝트 학습 데이터로만.
  5. 모델 설계 — 입력 → 토큰 → encoder → target의 shape; 아키텍처, pretraining 목표, 마스킹(있다면); 선택 하나를 7주차 mini-MAE 증거와 연결.
  6. 실행 전 파일럿 계획 — 7주차 코퍼스에서 mini-MAE 두 크기를 같은 시간 예산으로, 각각의 probe, 공개 모델의 짧은 적응 파일럿; compute 상한과 합격/불합격 기준. repo: data/, split manifest, 데이터 카드, BASE_MODEL_AUDIT.md.
11/233 · Pilot evidence and compute decision3 · 파일럿 증거와 compute 결정
  1. Pretrained-checkpoint diagnostic — frozen-probe result on your validation split and one failure example, before any substantial fine-tuning; native reconstruction or forecast output if applicable.
  2. Toy scaling evidence — two mini-MAE pilots → the one you chose → a ten-minute continuation with an interruption and resume → frozen probe; tokens processed, quality, memory, throughput; why you chose it.
  3. Adaptation pilot — tiny-batch overfit check, short learning curve, trainable layers or head, LoRA rank/alpha or full fine-tune; the resulting optimiser / LR / epoch recipe.
  4. Engineering evidence — data-loading and step time, precision, peak memory, a successful checkpoint resume.
  5. Quartet readiness — implementation status and tuning budget per row; random-init uses the same architecture and recipe; the supervised competitor is tuned to win.
  6. Go / shrink decision — projected GPU-hours for tuning, ≥ 3 seeds per stochastic row, one ablation with two settings, evaluation and a restart reserve; commit the run matrix before the full runs. Repo: eval/, pilot logs, resume evidence, run matrix, dated amendments; test still sealed.
  1. pretrained checkpoint 진단 — 본격 fine-tuning 전에 내 validation split의 frozen-probe 결과와 실패 사례 하나; 가능하면 원래의 복원·예측 출력도.
  2. 장난감 규모의 scaling 증거 — mini-MAE 파일럿 둘 → 선택 → 중단·재개를 포함한 10분 추가 학습 → frozen probe; 처리한 토큰 수, 품질, 메모리, 처리량; 왜 그것을 골랐나.
  3. 적응 파일럿 — 작은 배치 overfit 점검, 짧은 학습 곡선, 학습시킬 층·head, LoRA rank/alpha 또는 full fine-tune; 그 결과로 정한 optimizer / LR / epoch 레시피.
  4. 엔지니어링 증거 — 데이터 로딩과 step 시간, 정밀도, peak memory, checkpoint 재개 성공.
  5. 네 행의 준비 상태 — 행마다 구현 현황과 튜닝 예산; random-init은 같은 아키텍처·레시피, supervised 경쟁자는 이기도록 튜닝.
  6. 진행 / 축소 결정 — 튜닝, 확률적 행마다 seed 3개 이상, 설정 두 개짜리 ablation 하나, 평가, 재시작 여유분의 GPU-hours 예측; 본 실험 전에 run matrix를 commit. repo: eval/, 파일럿 로그, 재개 증거, run matrix, 날짜 적힌 수정 기록; test는 여전히 봉인.
